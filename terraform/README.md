# Self-Hosted Grafana on Azure Container Apps — POC

Goal: stand up real, self-hosted Grafana (not Azure Managed Grafana) as an
Azure Container App, wired to Azure Monitor for your Container Apps /
SAP metrics, and to Cloudflare + GitHub via the Infinity plugin. This is
sized as a demo POC — single replica, SQLite storage, minimal cost.

Two ways to provision the infrastructure — pick one:
- **`deploy.sh`** — imperative Azure CLI script, good for a quick one-off demo
- **`terraform/`** — the same resources as declarative IaC, good if this POC needs to be repeatable, torn down/recreated, or handed to a platform team afterward

Files in this folder:
- `deploy.sh` — Azure CLI provisioning script
- `terraform/` — Terraform equivalent (`providers.tf`, `variables.tf`, `main.tf`, `outputs.tf`)
- `provisioning/datasources.yaml` — Azure Monitor + Infinity datasource config, auto-loaded on boot
- `provisioning/dashboards.yaml` — tells Grafana where to find dashboard JSON
- `provisioning/fleetcart-overview.json` — starter dashboard (env variable, per-app filter, 4 panels)

Both tracks stand up the identical thing: resource group → Log Analytics
workspace → Container Apps Environment → storage account/file share with
the provisioning files uploaded → Grafana Container App (managed identity,
Infinity + Azure Monitor plugins) → Monitoring Reader role assignment.
Only use one track at a time against the same subscription to avoid
naming collisions (they default to the same resource names).

---

## 0. Prerequisites

1. Azure CLI installed (`az --version`) and logged in: `az login`
2. Correct subscription selected: `az account set --subscription "<sub-id-or-name>"`
3. Permissions to create resource groups, Container Apps, Storage Accounts,
   and role assignments in that subscription
4. A GitHub Personal Access Token (repo + actions read scope) — for step 5
5. A Cloudflare API token (Zone Analytics read) and your Zone ID — for step 5

---

## 1. Review and edit variables

Open `deploy.sh` and check the top "Variables" block:
- `LOCATION` — set to your nearest Azure region (default: `centralindia`)
- `RG`, `CAE_NAME`, etc. — rename if these clash with existing resources
- `GRAFANA_IMAGE` — pinned to `grafana/grafana-oss:11.2.0`; bump if you want latest

No other edits are required to get a working POC.

## 2. Run the deploy script

```bash
chmod +x deploy.sh
./deploy.sh
```

This takes roughly 4–6 minutes. Under the hood it:
1. Creates a resource group
2. Creates a Log Analytics workspace (Container Apps environments require one)
3. Creates the Container Apps Environment
4. Creates a Storage Account + Azure File Share — this is Grafana's persistent
   disk, holding the SQLite database, installed plugins, and the provisioning
   files above
5. Uploads `datasources.yaml`, `dashboards.yaml`, and the starter dashboard
   JSON into that file share
6. Registers the file share as environment storage, then deploys Grafana
   as a Container App with:
   - the Infinity and Azure Monitor plugins auto-installed on boot
     (`GF_INSTALL_PLUGINS`)
   - a **system-assigned managed identity** — this is what lets Grafana
     authenticate to Azure Monitor with zero stored secrets
   - the file share mounted at `/var/lib/grafana`
7. Grants that managed identity the **Monitoring Reader** role, scoped to
   the resource group, so Grafana can read Container Apps/SAP metrics
8. Prints the app URL, admin username, and a generated admin password

Keep the terminal output — the password isn't stored anywhere else.

### 2b. — OR — deploy with Terraform instead

```bash
cd terraform
terraform init
terraform plan    # review what it's about to create
terraform apply   # type "yes" to confirm
```

This creates the same resources as `deploy.sh`. Notes on the Terraform
version specifically:
- The admin password is generated by the `random_password` resource and
  written to Terraform state — treat `terraform.tfstate` as sensitive
  (it contains the password in plaintext). For anything beyond a demo,
  move state to a remote backend (see the commented `backend "azurerm"`
  block in `providers.tf`) and restrict who can read it.
- Get the outputs after apply:
  ```bash
  terraform output grafana_url
  terraform output -raw grafana_admin_password
  ```
- `provisioning_dir` defaults to `../provisioning` (relative to the
  `terraform/` folder) — the three provisioning files are uploaded via
  `azurerm_storage_share_file` resources, so re-running `terraform apply`
  after editing `fleetcart-overview.json` will re-upload it automatically
  (tracked via `content_md5`).
- To tear down: `terraform destroy`

## 3. Log in

Open `https://<the-fqdn-printed-above>` and log in with the admin
credentials from step 2. Grafana will prompt you to change the password
on first login — do that for anything beyond a throwaway demo.

You should already see:
- **Connections → Data sources**: "Azure Monitor" and "Infinity" pre-created
- **Dashboards → Fleet Cart Ops folder**: "Fleet Cart Ops - Overview (POC)"
  pre-loaded from the JSON file

## 4. Verify the Azure Monitor connection

Go to **Connections → Data sources → Azure Monitor → Save & test**. If the
managed identity role assignment propagated (can take a minute or two after
first deploy), this comes back green. If it fails immediately after
deploy, wait ~2 minutes and retry — Azure RBAC propagation lag is normal.

## 5. Add your GitHub and Cloudflare credentials

These are deliberately **not** in the provisioning file or the script, so
no token ever touches source control:

1. **Connections → Data sources → Infinity → Auth**
2. Add a new auth credential:
   - For GitHub: type "Bearer Token", paste your PAT, name it `github`
   - For Cloudflare: type "Bearer Token", paste your API token, name it `cloudflare`
3. Edit the two Infinity panels on the starter dashboard (GitHub Actions
   runs, Cloudflare requests) and attach the matching auth credential to
   each query
4. Replace the placeholder `<org>/<repo>` in the GitHub panel's URL and
   `<zone_id>` in the Cloudflare panel's query with your real values

## 6. Open the starter dashboard

**Dashboards → Fleet Cart Ops → Fleet Cart Ops - Overview (POC)**

What's already wired up:
- Top-of-page **time range picker** — Grafana's native one, with your
  15m/30m/1h/2h/6h/12h/1d/7d presets already configured
- **`$environment` variable** (dev/qa/stg/prd dropdown) and
  **`$container_app` variable** (search-app/pdp-app/bike-app/content-app/
  marketplace-app, multi-select) — these already parameterize the two
  Azure Monitor panels
- Requests/min and CPU% panels reading live from Azure Monitor
- GitHub Actions runs table and Cloudflare requests chart via Infinity

This is a starting point, not a finished dashboard — use it as scaffolding
and add panels for SAP Storefront metrics, deployment success rate, and
the other views from the original mockup directly in the Grafana UI (or
export the JSON and extend it programmatically).

## 7. Demo flow (suggested walkthrough order)

1. Show the time range picker switching 15m → 1h → 1d live
2. Switch the `$environment` variable dev → prd, show panels update
3. Multi-select two apps in `$container_app`, show the metrics narrow
4. Point to the GitHub Actions table updating with the latest real run
5. Point out this is a single Container App costing roughly $10–20/month,
   versus Managed Grafana Standard's per-seat pricing

## 8. Known POC limitations (call these out to stakeholders)

- **Single replica, SQLite backend** — fine for a demo, not for production
  HA. Scaling past 1 replica needs Grafana repointed at Postgres/MySQL.
- **No custom domain / TLS cert** — using the default
  `*.azurecontainerapps.io` FQDN and its managed cert.
- **Manual token entry** — intentional for security in a POC; a real
  rollout would pull these from Azure Key Vault via a Container Apps
  secret reference instead.
- **No alerting configured** — Grafana's alerting engine works out of the
  box against these same data sources, just not wired up here yet.

## 9. Tear down

If you deployed with `deploy.sh`, everything lives in one resource group:

```bash
az group delete --name rg-fleetcart-grafana-poc --yes --no-wait
```

If you deployed with Terraform, use Terraform so state stays in sync:

```bash
cd terraform
terraform destroy
```
